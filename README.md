# 乐玩魔方 🧊

一个纯前端的三阶魔方还原助手。把魔方六个面的颜色告诉它，它还你一组可以照着做的还原步骤。

**没有后端、没有构建、没有账号** —— 打开网页就能用，求解在本地浏览器里完成。

## 功能

- **📷 拍照识别**：对准魔方，九宫格实时显示识别到的颜色，一键读入当前这一面
- **✍️ 手动填色**：一次只填一面，填完自动提示往哪转；也能随时拖动魔方、自己挑任意一面填
- **🧊 3D 预览**：可拖动旋转的立体魔方，正对着自己的那一面就是正在填的面（黄色高亮）
- **▶️ 分步演示**：每一步都显示「转动前」的样子，并用黄色高亮标出这一步要转的面，支持自动播放与键盘操作
- **⚡ 平均 20 步**：Kociemba 两阶段算法，通常 19–21 步
- **🎨 任意配色都能用**：不要求「白顶绿前」。黄顶白底、蓝顶、日系配色都行 ——
  程序会根据你填的六个**中心块**自动判断哪个颜色代表哪一面
- **🔍 填错会指出来**：遇到凑不出来的状态，会告诉你是哪个角块/棱块对不上、
  最该复查哪几面，而不是丢一句「填色有问题」
- **↩️ 报错不用重填**：六面颜色全程存着，求解失败时点「返回修改」原样回到刚才那一版，
  还会直接跳到最可疑的那一面、把可疑格子标红，改完就能再试一次

## 部署到 Cloudflare Workers

项目根已带 `wrangler.jsonc`，把整个仓库目录作为静态资源目录。

> ⚠️ **必须保留 `assets.exclude` 里的 `node_modules`**。构建机在 `/opt/buildhome/repo`
> 里会先 `npm install`，而 wrangler 自带的 `node_modules/workerd/bin/workerd` 有 **147 MiB**，
> 一旦被当成静态资源就会报
> `Workers supports assets with sizes of up to 25 MiB`。排除掉之后实际上传约 350 KB。
> `.assetsignore` 是同一目的的第二道保险。

控制台设置（Workers & Pages → Create → Workers → 连接到 Git）：

- **Build command**：留空（纯静态，不需要构建）
- **Deploy command**：留空
- **Root directory**：`/`
- 部署分支选 `master`

如果想本地部署：

```bash
npx wrangler deploy
```

## 本地运行

因为用到了摄像头，浏览器只在 **https** 或 **localhost** 下才允许调用，所以请不要直接双击 `index.html`，而是起一个本地服务：

```bash
# 任选一种
python -m http.server 8000
npx serve .
```

然后打开 <http://localhost:8000>。

## 填色流程与约定

两个输入页共用一套「引导式单面填色」：

1. 立体魔方先正对着你露出**前面 (F)**，把它当成手里的魔方正对你的那一面。
2. 点右侧九宫格填 9 格颜色（先点调色板选色，再点格子；也可以连续点）。
3. 填满后自动转到下一面，并提示「整体往左转，把右面转到正对自己」，还能点**看演示**重播这次转动。
4. 从第二面起，六面都已解锁：**可以随意拖动魔方查看，也可以点任意一面直接填它**，不必按提示的顺序来。
5. 六面填满后「开始求解」按钮解锁。

> 关键前提：一旦定好「前面」，**整个采集过程中魔方不要再整体翻转**（转动某一层当然可以），
> 否则步骤会对不上。

### 算不出来的时候怎么办

求解失败不会把你打回空白页。报错页会：

1. 把**你填进去的那颗魔方**画出来（可拖动），最可疑的面标红；
2. 给两个出口 —— **「返回修改」**（保留六面颜色，回到填色页继续改）和
   **「六面全部重来」**（真的清空）；
3. 回到填色页后自动**跳到可疑格子最多的那一面**，顶部有提示条说明上次为什么失败，
   可疑格子用红框标出；改掉一格，那一格的红框就消失。

六面颜色全程存在 `sessionStorage` 里，所以浏览器**后退键**退回填色页也能接着改，
中途退出也不会丢（想彻底重来请点页面右上角的「清空」）。

贴纸下标采用 Kociemba 标准 facelet 顺序：面序 **U D F B R L**，每面 0–8 从左上角按行读。
标准顺序正好等价于「把这一面转到正对自己、且摆正」时看到的样子，
所以九宫格的格子可以和 `state[FS[f] + i]` 一一对应，不需要额外换算。

## 测试

```bash
npm install     # 只装 jsdom，用于页面测试
npm test
```

- `tests/engine.test.js`：转动表自洽性（转 4 次复原、互逆、中心不动）、
  非法状态的错误处理、**100 个随机打乱的端到端求解**
- `tests/colorscheme.test.js`：**配色无关性** —— 任意配色置换后依然可解
- `tests/cubies.test.js`：角块/棱块分组（出错定位的地基）
- `tests/viewmap.test.js`：九宫格格序与 Kociemba facelet 顺序一致
- `tests/pages.test.js`：用 jsdom 加载真实页面，检查 DOM 结构与完整交互链路
- `tests/deep.test.js`：**深层黑盒用例**（29 个 Use Case，74 项断言）—— 跨页链路、
  异常输入、求解压力、异步窗口、2000 次随机点击 fuzz、键盘快捷键、拍照路径
- `tests/recover.test.js`：**「报错后能回去改」专项**（18 个 Use Case，78 项断言）——
  草稿落盘 / 恢复 / 标红 / 清除 / 全部重来 / 草稿损坏容错，以及
  「报错 → 返回修改 → 改对 → 再求解」的完整闭环
  DOM 交互（点调色板 → 点格子 → 点面签 → 点按钮），刻意用**非标准配色**的魔方，
  覆盖引导填色、乱序切面、求解、逐步演示、非法输入诊断、随机打乱闭环、清空等。

还有一个变异测试脚本：

```bash
npm run test:mutation   # 故意把源码改坏，检验用例集能否报警
```

它注入 9 类缺陷（配色映射非双射、`isSolved` 写死、九宫格镜像、解法兜底被删、
填色写错面、草稿不落盘、草稿不恢复、不回写可疑格子、报错页没有返回出口），
逐一确认会被测试抓到 —— 用来防止「测试全绿但其实是摆设」。

### 三个已经踩过、现在有测试盯着的坑

1. **min2phase 遇到非法状态会静默返回空串**（不是 `"Error..."`），直接当「0 步解法」
   就会误报「已还原」。`js/solver.js` 会把解法真的转一遍验证，验证不过就报错。
2. **配色不能写死**。曾经把「白=U 黄=D 绿=F…」硬编码进 `TO_STD`，结果所有非标准配色的
   魔方一律求解失败 —— 连一个已经复原的魔方都报「无法还原」。现在颜色一律由
   六个中心块现场推导。
3. **复原判定不能写死成「面 f 必须是颜色 f」**，`isSolved` 同样要按中心块判断，
   否则第 2 条修好了也白搭。

## 浏览器支持

需要支持 CSS 3D Transform 与 Pointer Events 的现代浏览器。
摄像头识别要求 HTTPS 环境（localhost 除外）。
